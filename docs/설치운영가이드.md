# SRMS 설치·운영 가이드

시스템 유지보수 요청 관리(SRMS)를 서버에 설치하고 운영하는 방법입니다. 설계는 `설계서.md`, 개발 이력은 `개발관리.md`를 보세요.

관련 문서: [신규회사설치가이드.md](신규회사설치가이드.md)(다른 회사에 처음 설치), [사용자매뉴얼.md](사용자매뉴얼.md), [테스트시나리오.md](테스트시나리오.md), [유지보수인수인계.md](유지보수인수인계.md)(개발·AI 도구 인계).

## 1. 요구 사항

| 항목 | 내용 |
|---|---|
| PHP | 8.5.x (개발·검증 버전은 8.5.12 NTS). 확장: `pdo_sqlite`, `sqlite3`, `mbstring`, `fileinfo`, `openssl`, `ctype`, `filter`, `hash` (선택 `intl`) |
| SQLite | 3.35 이상(PHP 에 포함된 버전). WAL 모드 사용 |
| 웹서버 | Apache 2.4 또는 Nginx (설정 샘플: `deploy/`) |
| 메일 | 사내 SMTP 서버 (PHPMailer 7.2.0 이 `vendor/` 에 포함됨) |
| 브라우저 | 최신 Chrome/Edge, 해상도 1280px 이상 권장 |

외부 CDN 은 쓰지 않습니다(Bootstrap, Quill, SortableJS, Chart.js 모두 `public/assets/vendor` 에 포함).

## 2. 패키지 구성

```
public/        웹루트(여기만 웹서버에 노출)        app/       애플리케이션
database/      마이그레이션(스키마)                  bin/       CLI 도구
storage/       DB·첨부·로그·백업(웹루트 밖)          vendor/    PHPMailer
deploy/        Nginx/Apache/php.ini/스케줄러 샘플     docs/      이 문서
```

## 3. 설치 절차

1. 압축을 풀고 웹서버의 루트를 `public/` 으로 지정합니다(`deploy/nginx.conf.sample`, `deploy/apache.conf.sample` 참고). `app/`, `storage/`, `.env`, `database/` 가 URL 로 열리면 안 됩니다.
2. `.env.example` 을 `.env` 로 복사해 값을 입력합니다(§4). `.env` 는 PHP 실행 사용자만 읽도록 권한을 제한하세요.
3. `storage/` 에 PHP 실행 사용자의 쓰기 권한을 줍니다(`db`, `attachments`, `logs`, `backup`, `mail` 이 자동 생성됩니다).
4. 최초 설치(스키마 생성 + 기본 롤/권한/공통코드/기본 프로세스/메일 템플릿 + 첫 회사와 관리자):
   ```
   php bin/install.php --company=HQ --company-name="본사" --admin=admin --admin-name="관리자" --admin-email=admin@회사.com
   ```
   `--password` 를 생략하면 임시 비밀번호가 출력됩니다. 첫 로그인 후 `내 정보`에서 바꾸세요.
5. 점검: `php bin/doctor.php` — 모든 항목이 `[ OK ]` 이고 `[FAIL]` 이 없어야 합니다. `[WARN]` 은 아래 §6~§8 을 마치면 사라집니다.
6. SMTP 확인: `php bin/mailtest.php 받는사람@회사.com` (§6).
7. 주기 작업 등록(§7).
8. 브라우저로 접속해 로그인합니다.

회사(그룹사)를 추가하려면:
```
php bin/company.php add <코드> <회사명> --admin=ID --admin-name=이름 --admin-email=메일
php bin/company.php list
```
회사마다 롤/권한/공통코드/프로세스/메일 템플릿이 독립으로 만들어지고 데이터는 회사코드로 분리됩니다.

## 4. 환경 설정(.env)

| 키 | 설명 |
|---|---|
| `APP_ENV` | `production`(운영) / `local`(개발: 오류 상세 표시) |
| `APP_URL` | 메일 본문 링크에 쓰는 접속 주소(운영은 `https://...`). 하위 경로 배포면 `APP_BASE_PATH=/srms` |
| `APP_TZ`, `DEFAULT_LANG`, `ENABLED_LANGS` | 시간대, 기본 언어, 사용 가능한 언어(`ko,ja,en,zh`) |
| `DB_PATH`, `STORAGE_PATH` | SQLite 파일, 첨부·로그·백업·메일 파일의 기준 폴더. 모두 웹루트 밖 |
| `AUTH_MODE` | `LOCAL`(ID/비밀번호) / `SSO` / `BOTH`. SSO 는 §9 |
| `SINGLE_COMPANY` | 회사코드를 적으면 로그인 화면의 회사 선택이 사라지고 그 회사로만 로그인(단일 회사 운영용). 비우면 다중 회사 |
| `SESSION_LIFETIME_MIN`, `TRUST_PROXY` | 유휴 세션 만료(분). 리버스 프록시가 `X-Forwarded-Proto` 를 주는 경우에만 `TRUST_PROXY=1` |
| `SMTP_HOST/PORT/USER/PASS/SECURE`, `MAIL_FROM`, `MAIL_FROM_NAME` | 메일 서버(`SMTP_SECURE` = `tls`/`ssl`/`none`) |
| `MAIL_DRIVER` | `smtp` / `file`(`storage/mail` 에 .eml 저장, 개발용) / `off`(발송 보류). 비우면 SMTP_HOST 가 있으면 smtp, 없으면 개발=file·운영=off |
| `DUE_SOON_DAYS`, `SCHEDULE_RESPONSE_DAYS` | 단계 기한 임박 판단(영업일), 일정 변경 회신 기한(영업일) |
| `LIST_PAGE_SIZE`, `MAIL_LOG_PAGE_SIZE` | 요청 목록·메일 발송 이력의 한 페이지 건수(5~200). 비우면 각각 20, 30 |
| `BACKUP_PATH`, `BACKUP_KEEP_DAYS` | 백업 폴더(기본 `STORAGE_PATH/backup`), 스냅샷 보관 일수(기본 14) |

`.env` 를 고친 뒤에는 PHP-FPM/Apache 를 다시 읽을 필요가 없습니다(요청마다 읽음). 단, OPcache 를 쓰는 서버는 코드 교체 후에만 재시작이 필요합니다.

## 5. 롤과 기본 권한

| 롤 | 주요 권한 |
|---|---|
| 현업 사용자(`REQUESTER`) | 요청 등록, 본인 건 조회, 참조 건 조회, 단계 처리(요청자 단계: 보완/검수), 일정 변경 회신 |
| 현업 전산담당(`BIZ_IT`) | 위 권한 + 주관부서 건 조회, 리포트(주관부서 범위) |
| 전산팀(`IT_TEAM`) | 위 권한 + 전체 건 조회, 리포트(전체), 작업일지 등록·관리(`WORKLOG_REG`), 요청 분할·IT 담당자 지정(`REQUEST_SPLIT`) |
| 시스템관리자(`SYS_ADMIN`) | 모든 권한(사용자/롤/권한, 공통코드, 서비스, 프로세스 마스터, 메일 템플릿, 발송 이력) |

롤↔권한 매핑은 `관리 > 롤/권한` 에서 회사별로 바꿀 수 있습니다. 프로세스 수정은 `PROCESS_EDIT` 권한(기본: 시스템관리자)만 가능합니다.

## 6. 메일

- 상태가 바뀌면 메일이 대기열(`관리 > 메일 발송 이력`)에 쌓이고, 응답 직후 바로 발송을 시도합니다. 실패하면 5/15/60/240분 간격으로 최대 5회 재시도하고, 그래도 실패하면 `실패` 로 남습니다(이력 화면에서 `다시 보내기`).
- 운영 반영 전 `php bin/mailtest.php 받는사람@회사.com` 으로 SMTP 설정을 확인하세요. 대기열을 거치지 않고 바로 보냅니다.
- 템플릿은 `관리 > 메일 템플릿` 에서 언어별(ko/ja/en/zh)로 고칩니다. 수신자의 언어 설정으로 발송됩니다. 본문은 텍스트이며 변수는 `{request_no}`, `{title}`, `{step}`, `{link}` 등입니다(템플릿별 변수는 편집 화면 아래 목록 참조). 기본 제공 템플릿은 11종입니다.
- 이 개발 환경에는 메일 서버가 없어 실제 SMTP 전송은 검증하지 못했습니다(파일/메모리 전송으로 검증). **운영 반영 시 반드시 테스트 메일을 확인하세요.**

## 7. 주기 작업과 백업

`deploy/schedule.sample.txt` 를 참고해 등록합니다.

| 작업 | 권장 주기 | 내용 |
|---|---|---|
| `php bin/cron.php` | 1시간 | 기한 임박/초과 독촉, 일정 회신 독촉(매일), 메일 발송·재시도. 중복 실행은 잠금으로 막음 |
| `php bin/backup.php` | 1일 1회 | DB 스냅샷(`VACUUM INTO`, 무결성 검사 후 보관), 첨부 증분 복사, 보관기간 지난 스냅샷 삭제 |

**복원**: 서비스를 멈추고(또는 웹서버를 잠시 내리고) 백업 폴더의 원하는 `srms-YYYYMMDD-HHMMSS.sqlite` 를 `DB_PATH` 로 복사한 뒤 `-wal`, `-shm` 파일이 있으면 지우고 `php bin/migrate.php` 와 `php bin/doctor.php` 를 실행합니다. 첨부는 백업 폴더의 `attachments/` 를 `STORAGE_PATH/attachments/` 로 복사합니다. 백업 폴더는 다른 디스크/서버로도 복사해 두세요.

## 8. 웹서버/PHP 설정 요점

- HTTPS 로 운영하세요(HTTPS 요청에는 `Secure` 쿠키와 HSTS 헤더가 자동으로 붙습니다).
- `deploy/php.ini.sample` 의 값(`expose_php=Off`, `display_errors=Off`, 업로드 상한, 위험 함수 차단 등)을 적용하세요. 업로드 상한은 파일당 20MB(기본 정책), 한 요청 64MB 입니다. 웹서버의 본문 크기 제한도 맞춰야 합니다.
- `public/` 에서는 `index.php` 만 PHP 로 실행되도록 샘플이 막아 두었습니다. 첨부는 웹루트 밖 `storage/attachments` 에 난수 이름으로 저장되고, 다운로드는 권한을 확인한 뒤 PHP 가 내려줍니다.
- 로그는 PHP `error_log` 로 남깁니다(샘플: `storage/logs/php-error.log`).

## 9. SSO 연동(후속)

SSO 문서/라이브러리를 받으면 다음만 하면 됩니다.

1. `app/Auth/AuthProviderInterface.php` 를 구현하는 클래스를 만듭니다. `loginUrl($state)` 는 IdP 로그인 URL, `identify($query, $state)` 는 콜백 검증(서명/토큰/state) 후 `['company_cd' => ..., 'login_id' => 사번]` 을 돌려줍니다. 기본 구현 `SsoAuthProvider` 는 미연동 상태라 항상 거부합니다.
2. `app/Auth/Providers.php` 의 기본 어댑터를 새 클래스로 바꿉니다.
3. `.env` 에 `AUTH_MODE=BOTH`(SSO + 로컬) 또는 `SSO` 를 설정합니다. 로그인 화면에 `사내 SSO 로그인` 버튼이 나타납니다(`/sso/login` → IdP → `/sso/callback`).
4. 사번은 `user.login_id` 로 매핑합니다. 등록되지 않았거나 비활성인 사용자는 거부됩니다(자동 가입 정책은 SSO 구현 시 확정). 세션 생성·감사 기록은 공통(`Auth::attemptSso`)이며 `LOGIN_SSO` 로 남습니다.

초기 관리자와 SSO 장애 대비를 위해 운영 초기에는 `BOTH` 를 권장합니다.

## 10. 업그레이드

1. 백업(`php bin/backup.php`) 후 파일을 교체합니다(`.env`, `storage/` 는 유지).
2. `php bin/migrate.php` (스키마 변경 적용 + 새 기본 데이터 보강, 여러 번 실행해도 안전). 011 마이그레이션(투입시간)은 이전 `request.effort_md` 값을 옮기지 않고 버리므로, 이전 버전에서 올릴 때는 1번의 백업을 반드시 하세요.
3. `php bin/doctor.php` 로 점검합니다.

## 11. 보안 점검표(운영 반영 전)

- [ ] `public/` 만 웹루트이며 `/.env`, `/storage/`, `/app/`, `/database/` 가 404/403 이다
- [ ] HTTPS 이며 `APP_URL` 이 https 주소이고 `APP_ENV=production` 이다
- [ ] `expose_php=Off`, `display_errors=Off` (`php bin/doctor.php` 의 WARN 없음)
- [ ] 초기 관리자 비밀번호를 변경했고 불필요한 개발용 계정이 없다
- [ ] `.env`·`storage/` 권한이 PHP 실행 사용자에게만 열려 있다
- [ ] 메일 테스트(`bin/mailtest.php`), cron, 백업이 동작하고 백업 복원 연습을 1회 했다
- [ ] 방화벽에서 웹 포트 외 접근을 막았다

코드 차원의 보안(SQL 바인딩, 출력 이스케이프, CSRF, 회사 격리, 업로드 검사, 로그인 잠금, 보안 헤더)은 자동 테스트로 매 마일스톤 검증했습니다.

## 12. 문제 해결

| 증상 | 확인 |
|---|---|
| 로그인 화면은 뜨는데 모든 페이지가 404 | 웹서버가 존재하지 않는 경로를 `index.php` 로 넘기는지(`try_files` / `FallbackResource`) |
| 500 오류 | PHP `error_log` 확인, `php bin/doctor.php` 실행(권한/확장/마이그레이션) |
| 메일이 오지 않음 | `관리 > 메일 발송 이력` 의 상태/오류, `MAIL_DRIVER`, `php bin/mailtest.php` |
| 메일이 대기에서 안 나감 | `MAIL_DRIVER=off` 인지, cron 등록 여부(`doctor` 의 주기 작업 항목) |
| 로그인 5회 실패로 잠김 | 15분 후 재시도(`login_fail`), 관리자가 비밀번호 재설정 |
| `database is locked` | 백업/대량 작업과 겹치는 경우 일시적일 수 있음(busy timeout 5초). 반복되면 cron/백업 시각을 분산 |
