# SRMS 롤별 테스트 시나리오

시스템을 새로 설치했거나 코드를 고친 뒤 **화면에서 직접** 기능을 확인(인수 검증)하기 위한 시나리오입니다. 자동 테스트(`tests\run.php`)가 업무 규칙을 검증하고, 이 문서는 롤별 사용자 관점의 흐름과 권한 경계를 확인합니다.

## 0. 준비

### 0.1 환경

| 구분 | 방법 |
|---|---|
| 데모 환경(개발 PC, 권장) | `powershell -File tools\demo.ps1` → http://127.0.0.1:8081 (데모 DB 를 새로 만들고 서버 시작, 메일은 파일 저장) |
| 샘플 없이 시작 | `powershell -File tools\demo.ps1 -NoSamples` (§3~§7 의 E2E 를 처음부터 수행할 때) |
| 운영 이전 서버 | 설치 후 아래 계정을 **임시로** 만들고 확인이 끝나면 삭제(미사용 처리)하세요. 운영에서는 `bin/demo.php` 가 거부됩니다 |

데모 환경은 **자동 시연용이며 운영에서 실행할 수 없습니다.** 자동 테스트: `.\.tools\php\php.exe -c .tools\php\php.ini tests\run.php` 와 `powershell -File tools\check.ps1` 가 모두 통과해야 합니다(현재 214건, 128개 파일).

### 0.2 데모 계정과 구성

회사 `DEMO`, 모든 계정 비밀번호 `Demo1234`.

| 계정 | 롤 | 소속 | 비고 |
|---|---|---|---|
| `admin` | 시스템관리자 | 전산팀 | |
| `req1` 김요청 | 현업 사용자 | 영업팀 | |
| `req2` 박인사 | 현업 사용자 | 인사팀 | |
| `bizit1` 최현업전산 | 현업 전산담당 | 영업팀 | ERP 의 현업 IT 담당자(승인 담당) |
| `bizit2` 윤현업전산 | 현업 전산담당 | 인사팀 | HRS 의 승인 담당 |
| `it1` 정전산 | 전산팀 | 전산팀 | ERP 의 **전산 담당자**(수행 담당) |
| `it2` 한전산 | 전산팀 | 전산팀 | HRS 의 전산 담당자 |

서비스: `ERP`(주관 영업팀, 담당 it1), `HRS`(주관 인사팀, 담당 it2). 매핑: 모든 서비스의 `장애처리` = `긴급 장애`, 나머지 타입 = `일반 유지보수`.

샘플 요청 6건(`tools\demo.ps1` 기본): S1 완료(주문 화면 검색 조건 추가), S2 검토 대기(급여 명세서 양식 변경), S3 수행 중 + 일정 협의 대기(재고 현황 대시보드), S4 보완요청(퇴사자 데이터 정리), S5 긴급 장애 지연(주문 마감 배치 오류), S6 임시저장.

작업일지 샘플 2건(S7, S8; 사후등록 완료 건): `it1` 등록 "주문 조회 속도 문의 후 인덱스 점검"(요청자 `req1`, 전화), `it2` 등록 "급여 대장 재출력"(요청자 `req2`, 메일).

분할 샘플 1쌍(S9): `req1` 의 "주문·재고 화면 문구 일괄 수정"(ERP, 검토 대기)을 `it1` 이 분할해 "재고 화면 문구 수정(분할)"(담당자 `it2`)이 함께 있습니다.

### 0.3 사용 규칙

- 각 시나리오는 지정한 계정으로 **로그인한 상태**에서 수행합니다. 로그인은 회사 `DEMO` + 계정 + 비밀번호입니다.
- 메일 확인: 관리자 `관리 > 메일 발송 이력`(발송 방식: 파일 저장) 또는 `storage\mail\*.eml` 파일.
- 결과 칸에 `OK` / `NG` / `N/A` 와 비고를 적습니다. 실패(`NG`)는 재현 절차와 화면 캡처를 남기세요.
- 시나리오 번호의 접두어: `COM` 공통, `REQ` 현업 사용자, `BIZ` 현업 전산담당, `IT` 전산팀, `ADM` 시스템관리자, `E2E` 롤 간 연계, `SEC` 권한·격리·보안, `OPS` 운영.

### 테스트할 때 자주 오해하는 점(오류로 보이지만 정상 동작)

- **처리 버튼이 안 보임**: 단계마다 처리자가 다릅니다. 검토·종료는 `전산팀` 롤 전원(`it1`, `it2`), 승인은 **서비스에 지정된 현업 IT 담당자**(데모: ERP=`bizit1`, HRS=`bizit2`. 지정이 없으면 주관부서 현업 전산담당 전원), **수행은 서비스에 지정된 전산 담당자 한 명**(ERP=`it1`, HRS=`it2`), 검수는 요청자입니다. 예를 들어 ERP 요청의 수행 단계에서 `it2` 는 처리할 수 없습니다. 요청 상세 위쪽에 `현재 "수행" 단계는 ○○ 님이 처리합니다` 안내가 나옵니다.
- **한 사람이 여러 단계 처리**: 같은 사용자가 검토·종료(서비스 전산 담당자라면 수행까지)를 모두 할 수 있습니다(직무 분리 통제 없음). 분리가 필요하면 단계를 지정 사용자로 바꾸세요.
- **`일정 변경 요청` 입력란이 없음**: 접혀 있는 `일정 변경 요청` 버튼을 눌러 펼친 뒤 입력합니다. 요청자 본인에게는 제안 폼이 없습니다.
- **타인 요청 주소가 403 이 아니라 404**: 열람 권한이 없는 요청은 존재 여부를 숨기기 위해 404 로 응답합니다. 관리 화면은 권한이 없으면 403 입니다.
- **서버를 여러 포트로 동시에 띄우면 로그인이 풀림**: 브라우저 쿠키는 포트를 구분하지 않아 `127.0.0.1:8080`, `:8081` 같은 서버끼리 세션이 섞입니다. 다른 서버로 이동하면 `세션이 만료되었습니다`가 나오거나 로그아웃됩니다. 한 번에 서버 한 개만 띄우거나, 서로 다른 호스트 이름(`127.0.0.1` 와 `localhost`)으로 접속하세요.
- **로그인 계정을 바꿀 때**: 시크릿 창이 아니면 먼저 로그아웃하세요. 한 브라우저에서 두 계정을 동시에 쓸 수 없습니다.
- **프로세스 단계 편집**: 지정 버전 화면의 각 단계 `수정` 버튼을 눌러 펼친 뒤 입력합니다.
- **수행 단계 처리자가 서비스 담당자가 아닐 수 있음**: 전산팀이 요청별로 `IT 담당자`를 지정하면(IT-25) 그 요청의 수행 단계는 지정된 사람만 처리합니다. 서비스 담당자(예: ERP=`it1`)도 그 요청에서는 처리할 수 없고, 처리함·메일·리포트 담당자도 지정된 사람 기준입니다.
- **`SR 분할` 카드가 안 보임**: 진행 중인 일반 요청의 현재 단계가 검토·합의·승인·수행이고 일정 협의 중이 아닐 때, `요청 분할·담당자 지정` 권한이 있는 계정(전산팀, 시스템관리자)에게만 보입니다. 다른 서비스로 보내는 분할은 없습니다.
- **작업일지의 요청일과 등록일은 다른 값**: 목록·리포트의 기간은 입력한 **요청일**, 상세의 `등록일`은 실제 등록 시각입니다. 작업일지는 항상 완료·정시로 집계되고 알림 메일이 없습니다.
- **목록 건수는 `.env` 로 바뀝니다**: 요청·작업일지 목록은 `LIST_PAGE_SIZE`(기본 20), 메일 발송 이력은 `MAIL_LOG_PAGE_SIZE`(기본 30)입니다(OPS-11). 대시보드 표시 건수는 고정입니다.

### E2E-A: 일반 프로세스 정상 완료 (ERP / 기능수정)
